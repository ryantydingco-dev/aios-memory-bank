# Ryan Operating Style

## Working style
- Practical > theoretical.
- Wants systems that compound, not one-off outputs.
- Learns best when concepts are translated into business execution and concrete examples.
- Likes casual, direct, slightly goofy tone as long as the output is useful.
- Prefers direct challenge over agreeable flattery when the thinking is fuzzy or the plan has hidden risk.

## Infrastructure preference
- Build the machine underneath the work: memory, workflows, automations, review loops, and clear operating maps.
- Avoid noisy raw transcript dumps. Prefer clean summaries, decisions, open loops, and reusable workflows.
- Human-in-the-loop by default for risky actions.
- Surface source-of-truth conflicts before rippling changes through websites, outbound copy, docs, or campaign assets.

## Agent preference
- Agents should explain simply, then act.
- Agents should preserve context across tools instead of making Ryan repeat himself.
- Agents should challenge fuzzy thinking when useful, but not turn every task into a giant essay.
- Agents should be honest when they do not have verified facts, especially around new model releases or business-facing claims.
- Agents should prioritize shipped leverage: outbound assets, proof artifacts, automations, demos, and decisions that move a venture forward.
