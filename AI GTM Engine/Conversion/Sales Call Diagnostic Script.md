# Sales Call Diagnostic Script

## Purpose
Turn booked calls into qualified opportunities and closed deals by diagnosing the document-intake bottleneck before pitching.

## Call Frame
This should feel like a workflow audit, not a generic demo.

Opening:
```text
Appreciate you taking the time. My goal is simple: understand how borrower docs move from upload/email to lender-ready package, spot where the friction is, and see if Oloxa is actually relevant. If it's not, I'll tell you.
```

## 15-Minute Call Structure

### 1. Context — 2 minutes
- What types of deals are you mostly working on right now?
- How many active files/deals are you usually juggling?
- Who owns borrower document collection today?

### 2. Workflow Map — 5 minutes
Ask them to walk through the current process:
1. borrower sends docs
2. docs land where?
3. who opens/checks them?
4. who renames/files them?
5. who checks lender requirements?
6. who follows up on missing items?
7. when is a package considered lender-ready?

### 3. Pain Quantification — 4 minutes
- How many follow-ups happen on a typical deal?
- How much time gets lost to renaming/sorting/chasing/checking?
- What is the most annoying part?
- What happens when a package is incomplete?
- Does this block broker time, admin time, or lender turnaround?

### 4. Fit Check — 2 minutes
- If this layer were automated, what would need to be true for you to trust it?
- What would make it not worth changing?

### 5. Close / Next Step — 2 minutes
If fit is strong:
```text
Based on what you described, this sounds like the exact intake layer Oloxa is built for. The next useful step would be to map one real deal workflow and show how docs would be sorted, missing items flagged, and borrower follow-ups handled. Want to set up a deeper walkthrough?
```

If fit is weak:
```text
Honestly, if your current process is already tight and the volume isn't painful, this may not be urgent. I'll keep you in the loop if we build something more relevant for your setup.
```

## Qualification Criteria
A call is qualified if at least 3 are true:
- 5+ active deals/files at a time
- multi-lender or varied checklist workflow
- borrower follow-up happens manually
- admin/broker spends hours sorting/renaming/checking docs
- missing docs delay lender-ready submission
- team is hiring/adding support due to volume
- decision maker cares about faster submissions or more capacity

## Close Fast Indicators
- Explicit pain around chasing docs.
- Hiring admin/processor support.
- Deal packages delayed by incomplete borrower docs.
- Founder/partner says brokers are doing admin work.
- They ask about implementation, accuracy, integrations, or timeline.

## Deal Risks
- Too low deal volume.
- Residential/simple files only.
- No budget or no owner of process.
- They only want generic CRM/storage.
- Trust concern around AI classification with no willingness to test.
