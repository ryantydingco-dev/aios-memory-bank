# Video Teardown - Hermes Desktop App and AIOS Operating System

Source: https://www.youtube.com/watch?v=63zp4Ie7j5c
Created: 2026-06-03

## Big idea

Hermes Desktop makes agentic workflows easier for non-technical users by putting sessions, skills, tools, messaging platforms, models, and cron jobs into a visual interface instead of requiring terminal setup.

For Ryan: this validates the AIOS Quickstart delivery story. Small businesses do not want to understand terminal commands, MCP, provider configs, or cron syntax. They want installed routines they can access from familiar places like Telegram, Slack, email, or a shared workspace.

## Key takeaways

### 1. Desktop app lowers the setup barrier

The video shows Hermes moving from terminal-first to desktop-first: install app, start a session, browse skills/tools, configure messaging.

Ryan translation: AIOS Quickstart should not feel like "custom AI engineering." It should feel like a practical business workspace with 3 installed routines and clear instructions.

### 2. Skills are the product packaging layer

Hermes ships with skills like humanizer, Excalidraw, Google Workspace, Notion, Linear, and PowerPoint.

Ryan translation: the mortgage AIOS routines should become reusable skills/SOPs:

- Missing-doc follow-up drafts
- Daily pipeline brief
- Stale borrower/realtor follow-up queue
- Complex loan checklist generator
- Reply/objection classifier

The client should see these as named routines, not a mysterious AI blob.

### 3. Messaging is the killer interface

The video highlights Telegram/WhatsApp/Slack setup. This matters because business owners already live in messaging.

Ryan translation: for remote delivery, the client experience can be:

- owner/team sends workflow update or pasted pipeline summary
- agent returns draft brief/follow-up queue
- human approves before anything goes out

This is easier to sell than "log into this complicated AI dashboard."

### 4. Cron jobs make routines real

The video shows Hermes cron jobs / scheduled tasks. Daily briefs are a perfect use case.

Ryan translation: every AIOS Quickstart should include at least one scheduled routine:

- Monday morning business brief
- daily pipeline/admin brief
- Friday stale-follow-up review

Routines that show up on schedule feel like employees. Prompts that sit in a doc feel like homework.

### 5. Always-on matters

The video warns: if Hermes Desktop runs on your laptop and the laptop is off, cron jobs do not fire.

Ryan translation: for client delivery, do not promise 24/7 reliability from a laptop install. Either keep v1 as client-run/manual approval routines, or use a proper always-on setup later: Mac Mini, VPS, managed gateway, or hosted service.

### 6. Hermes is not yet the best coding desktop app

The creator says Claude Code/Codex are still more advanced for desktop coding workflows. Hermes' edge is messaging + model flexibility + skills + scheduling.

Ryan translation: do not position AIOS as "best coding agent." Position it as a business operations layer.

## What this means for AIOS Quickstart

This video supports the offer:

"I install 3 approval-only AI routines your team can actually use from your normal workflow. No sensitive borrower files needed for v1. No auto-sending."

The visible deliverable should be:

- named routines
- operating guide
- approval rules
- optional Telegram/Slack/email interface
- scheduled brief if appropriate
- Loom walkthroughs

## What this means for outbound

Good opener angle:

"Most mortgage teams do not need a giant AI strategy. They need 2-3 recurring admin routines that show up when needed and stay approval-only."

Follow-up proof angle:

"For version one, I keep this away from sensitive borrower docs. It drafts/briefs/queues using approved templates and sanitized examples."

## Bullshit / caution

Do not oversell Hermes Desktop as a turnkey client platform yet. The video itself says it is new and cron jobs require the machine to stay on. For client work, keep the promise operational, not technical.

Avoid:

- "24/7 autonomous employee" unless infrastructure is actually always-on
- "fully automated mortgage ops"
- direct borrower-doc ingestion in v1

## What I'd actually do

1. Package the AIOS Quickstart deliverables as 3 named routines, like Hermes skills.
2. Keep delivery remote and approval-only.
3. Use scheduled briefs for Ryan's own GTM system first.
4. For clients, offer messaging interface as optional later, not required in v1.
5. If selling ongoing managed AIOS, eventually host it on always-on infrastructure.

## One-line lesson

Hermes Desktop proves the business opportunity: agents make money when they are packaged as simple, named routines that show up inside the places people already work.
