# Objection Response Library

## Purpose
Give Ryan/Sway fast, calm responses to common Oloxa objections while capturing market learning.

## Objection: We already have a process
Response:
```text
Makes sense — most good shops do. The question we usually look at is how much of that process still relies on humans opening attachments, renaming files, checking missing items, and chasing borrowers. Oloxa is meant to push the team toward exception review, not replace a process that already works.
```

Learning tag: PROCESS_EXISTS

## Objection: We have an admin/team for this
Response:
```text
Totally — and we don't position this as replacing that person. The better fit is giving them leverage so they're not stuck doing repetitive file cleanup and follow-up across every deal. They still own exceptions and judgment.
```

Learning tag: ADMIN_TEAM

## Objection: Our files are too custom
Response:
```text
That’s usually the right concern. We’d want to test it against real deal files/checklists before making any claims. Oloxa is strongest where there are repeated document types plus messy borrower behavior, not where every file is completely bespoke.
```

Learning tag: CUSTOM_FILES

## Objection: Borrowers are the bottleneck
Response:
```text
Exactly — that’s why the follow-up layer matters. Sorting docs is only part of it. The bigger value is knowing what’s missing and nudging borrowers without the broker/admin manually chasing every item.
```

Learning tag: BORROWER_BOTTLENECK

## Objection: We use Dropbox/Drive/CRM already
Response:
```text
That makes sense. We usually sit before/around storage — the messy part is getting borrower files cleaned up, named correctly, checked against requirements, and followed up on before they become a clean folder/package.
```

Learning tag: STORAGE_TOOL

## Objection: Is it secure/compliant?
Response:
```text
Fair question. For any serious fit, security and document access would need to be handled carefully. The first conversation is usually just to map the workflow and see whether the bottleneck is worth solving before we get into implementation details.
```

Learning tag: SECURITY

## Objection: Not a priority right now
Response:
```text
No worries. Is that because doc intake is already smooth, or because the pain exists but other things are ahead of it? Trying to understand whether we’re off on timing or off on the problem.
```

Learning tag: TIMING

Sure. Short version: Oloxa helps commercial finance teams turn messy borrower uploads into cleaner lender-ready packages — docs sorted/renamed/filed, missing items flagged, and borrower follow-ups automated.
