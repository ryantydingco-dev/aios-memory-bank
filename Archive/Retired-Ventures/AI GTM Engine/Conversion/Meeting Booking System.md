# Meeting Booking System

## Purpose
Turn outreach replies into booked Oloxa sales calls as fast as possible.

## Conversion Principle
The outreach goal is not to explain Oloxa. The outreach goal is to earn the next micro-commitment:

1. reply
2. permission to send quick example / Loom
3. 15-minute diagnostic
4. full demo / workflow audit
5. implementation conversation

## Fastest CTA Ladder

### CTA 1 — Soft Reply Ask
Use in cold first touch.

```text
Worth comparing notes?
```

```text
Worth me sending a quick example?
```

### CTA 2 — Permissioned Example
Use after interest or positive signal.

```text
Makes sense. I can send a quick 60-sec example of how we handle borrower docs → sorted/renamed files → missing-doc flags → borrower nudges. Want me to send it here?
```

### CTA 3 — Diagnostic Call
Use when they confirm relevance.

```text
If useful, happy to do a quick 15-min deal paperwork audit. We can map where docs slow down before lender submission and see if Oloxa would actually save time. Want to compare calendars?
```

### CTA 4 — Direct Booking
Use when pain is explicit or they ask for details.

```text
Worth putting 15 mins on the calendar? Goal would just be to see whether your intake/follow-up process has enough volume for Oloxa to matter.
```

## Reply Routing

### Positive / Curious
Move quickly to example or meeting.

Response:
```text
Totally. The short version: Oloxa handles the intake layer — borrower docs get sorted/renamed/filed, missing items get flagged, and borrower nudges go out automatically. Usually easiest to show with an example. Want me to send a quick walkthrough or compare notes for 15 mins?
```

### Already Have Process
Do not fight them. Reframe as exception handling and admin leverage.

```text
That makes sense — most good shops already have a process. The question we usually look at is where the process still needs humans to rename/sort/chase/check missing items. Oloxa is meant to push the team toward exception review, not replace the process. Worth a quick compare?
```

### Not Interested
Ask one learning question if appropriate.

```text
No worries. Quick gut check so I don't misread the market — is doc intake/follow-up just not a painful bottleneck for your team, or is it handled well already?
```

### Send Info
Do not send a brochure dump. Send concise example + CTA.

```text
Sure — quick context: Oloxa helps commercial finance teams turn messy borrower uploads into cleaner lender-ready packages. It sorts/renames/files docs, flags missing items, and nudges borrowers automatically. Proof point we use: 7+ hours saved per deal and 97% classification accuracy.

If I sent a 60-sec walkthrough, what type of deal/package would be most relevant to show?
```

## Meeting Qualification Questions
Use these before or during the call:

1. How many active deals/files are you usually managing at once?
2. Who collects borrower documents today?
3. Where do files usually get messy — naming, missing items, lender checklist variation, follow-up, or handoff?
4. How often do lender-ready packages get delayed because docs are incomplete?
5. What happens when borrowers ignore follow-ups?
6. Do you use a consistent checklist by lender/deal type?
7. If this saved 5–7 hours per deal, where would that time go?

## Booking Rules
- Do not over-explain before booking.
- Keep calls framed as audits/comparisons, not generic demos.
- The call should diagnose their actual intake workflow before pitching.
- Use calendar link only after there is enough interest, unless a campaign is intentionally direct-booking.
