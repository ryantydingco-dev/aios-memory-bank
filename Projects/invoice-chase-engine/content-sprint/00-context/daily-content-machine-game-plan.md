# Daily Content Machine Game Plan

## Goal

Make the YouTube + Ideabrowser business experiment easy enough that Ryan can sit down, hit record, and build one useful proof artifact every day.

The machine is not:

- a generic content calendar
- a new content strategy
- a guru funnel
- a list of random AI ideas

The machine is:

```text
Ideabrowser idea
-> boring business angle
-> one visible proof artifact
-> YouTube episode
-> Shorts/Reels
-> LinkedIn posts
-> outbound/business test
-> review what worked
```

## Ryan filter

Use this filter before picking any idea:

1. **Boring workflow with money attached**
   - invoicing
   - lead follow-up
   - proposals
   - compliance
   - reporting
   - enrichment
   - quote generation
   - documentation

2. **Can be shown on screen**
   - checklist
   - calculator
   - dashboard
   - workflow map
   - scraped lead list
   - audit report
   - before/after demo
   - landing page
   - email sequence

3. **Can be tested as a service first**
   - audit
   - done-for-you setup
   - implementation sprint
   - template pack
   - managed workflow

4. **Can be explained in one sentence**
   - "I am testing whether [buyer] will pay for [workflow outcome]."

5. **Does not require Ryan to fake proof**
   - no invented revenue
   - no fake customers
   - no fake testimonials
   - no fake screenshots

## The daily command

Ryan should be able to start each day by saying:

> Run today's Ideabrowser YouTube episode machine. Pick one boring business idea that fits my Ryan filter. Build the episode pack, visible proof artifact, Shorts scripts, LinkedIn posts, hooks, and completion summary. Keep it YouTube-first, proof-on-screen, story-first, no guru energy.

Codex should then create the files inside the current content sprint folders:

```text
01-proof-pack/todays-youtube-episode-pack.md
02-linkedin/posts.md
03-short-form/scripts.md
04-sales-assets/[episode-artifact].md
05-hooks/hook-bank.md
06-review/codex-completion-summary.md
```

## Daily operating loop

### Step 1 - Pick the idea

Use Ideabrowser as the source of truth.

Priority order:

1. Saved Ideabrowser projects
2. High-opportunity Ideabrowser ideas
3. Ideas related to the current YouTube arc
4. Viewer/comment/customer-requested workflows

Decision rule:

Pick the idea that gives Ryan the clearest screen artifact today.

Not the biggest market.
Not the fanciest product.
Not the most impressive technical build.

The one Ryan can show.

### Step 2 - Convert the idea into a boring business test

Every idea becomes this:

```text
Buyer:
Pain:
Current broken workflow:
AI-assisted workflow:
Visible artifact:
First paid offer:
Test this week:
```

Example:

```text
Buyer: QuickBooks businesses chasing invoices manually
Pain: open invoices slip overdue after they are sent
Current broken workflow: owner emails clients one by one
AI-assisted workflow: QuickBooks-connected follow-up sequences
Visible artifact: AR Leak Audit checklist
First paid offer: $500 AR Leak Audit
Test this week: send artifact to 20 business owners/accountants
```

### Step 3 - Build one proof artifact

Every episode needs one artifact Ryan can scroll, demo, or explain.

Good daily artifacts:

- audit checklist
- simple calculator
- workflow map
- lead scoring sheet
- outbound script pack
- landing page draft
- CSV template
- prompt library
- before/after process map
- mini dashboard
- teardown report

Bad daily artifacts:

- abstract strategy
- vague notes
- giant roadmap
- "AI will change X" essay
- anything that cannot be shown on screen

### Step 4 - Create the episode pack

Every YouTube pack should include:

- title
- premise
- why it is interesting
- cold open
- 8-12 minute structure
- key talking points
- what to show on screen
- where Ideabrowser fits
- where Claude fits
- where Codex fits
- where Hermes fits
- monetization angle
- soft CTA
- recording checklist

The episode structure should usually be:

```text
0:00 Cold open with the business problem
0:45 The real story or idea source
2:00 The workflow leak
3:30 What Ryan is building today
5:00 Screen artifact walkthrough
7:00 How the AI tools helped
8:30 Business test / monetization angle
10:00 Soft CTA
```

### Step 5 - Repurpose only after the YouTube spine exists

Shorts and LinkedIn should come from the episode, not the other way around.

Daily repurposing pack:

- 5 Shorts/Reels scripts
- 3 LinkedIn posts
- 30 hooks/title ideas

Shorts should come from:

- the weirdest insight
- the most painful workflow leak
- the business-owner moment
- the visible artifact
- the monetization test

LinkedIn should be:

- story first
- useful
- casual
- slightly funny
- no fake authority pose

### Step 6 - Record with the pack open

Ryan should not memorize scripts.

Ryan should record with:

1. episode pack open
2. proof artifact open
3. Ideabrowser idea/project open
4. Claude/Codex output visible if useful
5. one sentence written on screen:

```text
Today I am testing whether [buyer] will pay for [workflow outcome].
```

Recording rule:

If stuck, return to the artifact and explain the next line.

## Daily time box

### 75-minute version

```text
0-10 min: pick Ideabrowser idea
10-20 min: frame boring business test
20-40 min: build proof artifact
40-55 min: generate episode pack + repurposing
55-70 min: record YouTube
70-75 min: note business test + next outreach
```

### 30-minute emergency version

```text
0-5 min: pick idea
5-15 min: build checklist/workflow artifact
15-25 min: record rough episode
25-30 min: create title, CTA, and 3 shorts hooks
```

The emergency version still needs one visible artifact.

## Tool roles

### Ideabrowser

Idea source and research layer.

Use it to:

- find high-opportunity ideas
- pull saved projects
- compare opportunity/pain scores
- find business model hints
- avoid starting from a blank page

Ideabrowser is the quarry.

### Claude

Reasoning and language layer.

Use it to:

- map the workflow
- identify leaks
- draft scripts
- write customer-safe explanations
- structure offers
- turn messy thoughts into a clear story

Claude is the strategist/writer.

### Codex

Build and packaging layer.

Use it to:

- create the daily files
- build the artifact
- make calculators/templates/checklists
- maintain the content sprint folder
- turn the episode into reusable assets

Codex is the production operator.

### Hermes

Review and quality-control layer.

Use it to:

- flag hype
- flag unsafe claims
- tighten the hook
- check whether the artifact is useful
- decide what is unclear before Ryan records

Hermes is the critic.

### Ryan

Judgment, taste, proof, and reps.

Ryan does:

- choose the final idea
- decide what is honest enough to show
- record the imperfect rep
- test demand
- talk to prospects
- decide what gets repeated

Ryan is the operator.

## Weekly rhythm

### Monday - Queue day

Pick 5 candidate Ideabrowser ideas.

For each:

- title
- buyer
- workflow leak
- artifact idea
- first paid offer
- why this fits Ryan

Then choose the first episode.

### Tuesday-Friday - Build and record

One idea per day.

Output:

- 1 YouTube episode
- 1 proof artifact
- 5 Shorts scripts
- 3 LinkedIn posts
- 1 business test

### Saturday - Review

Look at:

- which title was clearest
- which short had the strongest hook
- which artifact could be sent to prospects
- which idea produced the easiest episode
- which idea created buyer curiosity

### Sunday - Preload

Set up next week's queue.

Do not over-plan. Pick the next five.

## The three recurring episode formats

### Format 1 - "Can this be a business?"

Use when testing a new idea.

Structure:

- Ideabrowser found this
- here is the boring pain
- here is the buyer
- here is the artifact
- here is the paid test
- here is what I would do tomorrow

### Format 2 - "I built the first artifact"

Use when the idea already feels worth testing.

Structure:

- the workflow is broken
- I built the checklist/calculator/map
- here is what it catches
- here is who I would send it to
- here is the CTA

### Format 3 - "I tested demand"

Use after outbound or posting.

Structure:

- here is what I sent
- here is who I sent it to
- here is what happened
- here is what I learned
- here is what changes next

## Automation roadmap

### Version 1 - One-command daily pack

Ryan says the master prompt.

Codex:

- pulls Ideabrowser profile/projects/ideas
- picks the daily idea
- creates all six files
- creates the visible artifact
- summarizes what to record first

This is enough to start.

### Version 2 - Weekly idea queue

Add one file:

```text
00-context/weekly-idea-queue.md
```

Codex updates it every Monday with 5 candidate ideas.

Ryan only chooses from the queue during the week.

### Version 3 - Daily episode folder generator

Add a tiny script or template command that creates:

```text
episodes/YYYY-MM-DD-[idea-slug]/
```

With subfolders:

```text
proof-pack/
artifact/
shorts/
linkedin/
hooks/
review/
```

Use this once the current flat sprint folders start feeling crowded.

### Version 4 - Publish/review loop

Track:

- episode title
- idea source
- artifact type
- CTA
- short hooks
- views
- comments
- DMs
- outbound replies
- booked calls

The content machine becomes useful when it tells Ryan:

```text
Make more episodes like this.
Stop making episodes like that.
This artifact got buyer replies.
This one was just interesting content.
```

## Starting recommendation

Do not overbuild the automation yet.

Start with Version 1 for 7 days:

1. Use the master prompt every morning.
2. Let Codex create the pack.
3. Record the episode with the artifact open.
4. Post one short and one LinkedIn post.
5. Send the artifact to 5 prospects or relevant people.
6. Review on day 7.

The first goal is not perfection.

The first goal is to make daily recording feel obvious.
